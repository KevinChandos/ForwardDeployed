## Key Design Decisions
| Decision | Rationale |
|---|---|
| Wishlist nested under `/users/me/wishlist` | Wishlist is always member-scoped; flatter than `/wishlist/{wishlistId}` |
| Guest token via `X-Guest-Token` header | Avoids polluting the Authorization header; enables cart/checkout without authentication |
| Coupon FK deferred to checkout flow | `POST /checkout/{sessionId}/coupon` applies coupon; `POST /coupons/validate` is a stateless preview |
| Payment confirm is client-initiated | Razorpay/Stripe pattern: client calls gateway, then notifies backend with signature; prevents race with webhook |
| Reviews nested under `/books/{bookId}/reviews` | Reviews are always in context of a book; matches PDP wireframe |
| Checkout as a separate session resource | Models the DDD CheckoutSession aggregate; separates cart from order creation |
| `MoneyDTO.amount` as string | Prevents IEEE-754 floating-point precision loss in JSON parsing |
| Author follow endpoints nested under `/users/me/authors` | Ownership is member-scoped; consistent with address and wishlist patterns |
